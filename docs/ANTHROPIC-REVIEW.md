# Directory review boundary

The core package has 30 entry skills, eight lead agents, eight commands and eight departments. All 190 detailed workflow guides and 16 original role cards remain readable as references. It ships on-demand, readable JavaScript helpers and one square fallback PNG for the host's icon discovery. The approved v9 logo and banner live at the repository root, and v9 was uploaded separately to the directory listing. No script reads or executes the fallback PNG. There are no startup hooks, declared MCP servers, dependency installs, binary executables or automatic paid research in core.

## Credential warning

The directory scan of v2.3.0 reported `MCP_FORWARDS_CREDENTIAL_ENV` against `.claude-plugin/plugin.json`, without identifying a specific credential reader or outbound transfer in the core. The core manifest has no `mcpServers`, `userConfig`, `hooks` or `dependencies`; core JavaScript helpers do not read environment credentials or contact a remote service. The package validator rejects credential-shaped files, common secret patterns, private build-environment examples, environment reads and common network/subprocess calls in core helpers. A separately installed research integration has its own manifest and declared HTTPS connection with a required sensitive `${user_config.apify_token}` value; it is not included in the core directory submission.

Controlled scans of v2.3.5, v2.3.6 and v2.3.7 removed the owner-operated research CLI guide, inline bearer-forwarding examples and direct token lookup examples in succession. Each scan still reported the same single manifest-only credential warning, with no findings fixed. Those changes were therefore not evidence of a credential-forwarding defect in the submitted core; v2.3.8 restores the useful owner-operated and secure-storage material while retaining the safer app-owned auth-client examples. The core research guide still forbids assistant discovery or reuse of installer credentials. The [technical data-handling page](CLI-DATA-HANDLING.md) identifies optional destinations and boundaries. A reviewer must inspect the exact execution path or identify a concrete file before this warning can be resolved confidently. If they identify one, fix that path and revalidate it.

For v2.3.9, reviewer-only scan history and full technical destination disclosure moved to repository-level documentation outside the submitted plugin folder. This removes the installed core's literal `user_config` and research endpoint references while keeping the disclosures available. A fresh directory scan must determine whether those references caused the generic warning. The optional research plugin remains separate and now provides credential-isolated public Actor discovery through the installed CLI.

For v2.4.1 (952ad86), the optional research connection moved to its own repository, [mobile-app-builder-research](https://github.com/khadinakbarlabs/mobile-app-builder-research), leaving this repository with no MCP server, `userConfig`, connector header or credential configuration. The directory scan of v2.4.1 passed security and still reported the same manifest-only `MCP_FORWARDS_CREDENTIAL_ENV` warning, so the sibling connector was not its source. The version is waiting for a reviewer; do not change files for this warning again until a reviewer names a concrete file or data flow.

## Listing and image notes

The `icon`, `documentationUrl`, `supportUrl`, `privacyPolicyUrl` and `termsOfServiceUrl` fields are [documented directory listing fields](https://code.claude.com/docs/en/plugins-reference), but the v2.3.0 scan reported them as unrecognized or cross-tool. The submitted directory listing had already imported the links, and its icon was replaced with the v9 image in the directory editor. The listing editor says newer versions do not update those imported details. Version 2.3.2 omitted these five fields from the runtime manifest and moved the v9 images outside the installed root, fixing seven scanner findings. Its scan then introduced a “No icon” warning. Version 2.3.3 supplies the default package icon path with previously scanned artwork while retaining the uploaded v9 listing icon. Confirm the listing still shows the links and v9 icon after the new scan; re-add listing fields if a future fresh submission requires manifest-based import.

The v2.3.8 screenshot calls `ASSETS_PASSED_UNREAD` a validation note about `.claude-plugin/icon.png`, not a failed image check or a policy hold. The fallback PNG decodes fully in local validation, and no plugin script reads or executes it. Removing it previously exchanged this note for a “No icon” warning. Keep the icon unless the directory accepts an equally visible, validated alternative.

Local validation and a completed security scan are separate from a reviewer decision and a live listing. Read the exact version's directory status before claiming publication.
