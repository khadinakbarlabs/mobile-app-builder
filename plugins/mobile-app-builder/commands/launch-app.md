# launch-app

Apply [the context and reporting workflow](../docs/INTELLIGENT-WORKFLOW.md). For ongoing release checks that the user requests, use the bounded [recurring-work recipes](../docs/RECURRING-WORK.md).

Read only the entry skills relevant to the request: [guide-metadata-assets](../skills/guide-metadata-assets/SKILL.md), [guide-build-signing](../skills/guide-build-signing/SKILL.md), [guide-submission-rollout](../skills/guide-submission-rollout/SKILL.md), [guide-launch-planning](../skills/guide-launch-planning/SKILL.md).

Audit actual build and assets; prepare metadata, screenshots and release checklist; keep source, signing, device, store and public availability evidence separate.

Start from the context the user provides. Ask only for a missing fact that changes the next action; continue independent work. Preserve unrelated changes. Paid research, account operations, deployments and publication follow the user's actual authorization.

Finish with the result, verification evidence, limitations and next concrete action.
